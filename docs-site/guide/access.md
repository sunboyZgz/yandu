# 独立密码保护

管理页私密，不代表发布的资源私密。你需要在每个项目中选择资源访问权限。

## 公开只读

明确确认应用后，访问者可以读取匹配资源范围内、符合媒体策略的文件。资源只接受 GET/HEAD，不提供上传或磁盘修改功能。

云端清空网站 Cookie 和 Authorization，再将公开资源请求送往本机。资源响应也不能设置网站 Cookie。

## 设置独立资源密码

在项目表单选择“独立密码保护”，填写资源用户名和密码：

- 密码需要满足服务端的 12–72 字节限制；使用 ASCII 字符时，一个字符对应一个字节。
- 使用独立凭据，不要填写网站登录密码或服务器 root 密码。
- 已有密码项目编辑时，密码留空可保留原密码。

保存并确认应用后，访问者会收到 Basic 密码挑战。云端会保留独立资源 Authorization，密码不会以明文保存到数据库。

## 完成受保护资源验证

由于工具不持久化明文密码，受保护项目在入口接入后需要额外验证：

1. 进入“服务器连接”。
2. 在“验证密码资源”中选择项目。
3. 输入资源密码并提交验证。
4. 检查项目是否变为“已生效”。

只把业务网站的通用 200 页面返回给探针，不会被判定为成功。验证读取的是当前随机资源内容。

## 修改权限或密码

访问策略、用户名或密码变更会先阻断本地资源并停用。重新确认应用后再恢复入口；云端同步失败不能让资源回到旧的公开权限。

已被访问者下载的文件无法召回。

## 缓存选择

| 策略 | 适用情况 |
| --- | --- |
| 每次重验证 | 默认选择，可在相同 URL 更新素材 |
| 长期不可变缓存 | 仅用于内容哈希命名、内容不再变更的文件 |
| 密码资源 | 自动使用 private/no-store |

独立资源密码不等于业务登录。签名链接、业务账号、私密相册授权和上传服务属于后续独立功能。
