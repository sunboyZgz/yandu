# 创建与发布项目

一个项目关联一个素材根目录、一个授权站点和一组资源前缀。多个项目可以使用同一网站，但资源范围不能重叠。

## 创建草稿

在“项目管理”点击“新建项目”，填写表单：

| 字段 | 应如何填写 |
| --- | --- |
| 项目名称 | 便于自己识别，例如“个人博客” |
| 项目标识 | 小写字母开头，使用字母、数字或连字符，例如 `blog` |
| 本地素材目录 | 绝对路径，例如 `D:/oss/blog` |
| 网站站点 | 从连接包提供的授权站点中选择 |
| 页面基础路径 | 转换文件路径时去除的部分，例如 `/blog` |
| 资源路径范围 | 每行一个，例如 `/blog/xxx/`，以 `/` 结尾 |
| 访问权限 | 公开只读，或独立密码保护 |
| 缓存策略 | 默认“每次重验证” |

没有授权过的目录，需要勾选“我授权檐渡管理并读取这个素材目录”。请核对表单中的路径预览，再点击“保存项目”。

保存创建的是草稿，状态为“未发布”。它不会同步一个公开入口。

## 确认并应用

点击项目行的“应用”。确认窗口会列出素材目录与资源路径范围。

公开只读允许互联网上的访问者读取这些媒体；密码保护需要独立资源密码。确认符合原有发布规则后，勾选确认项并点击“确认并应用”。

后台按顺序完成：

1. 检查目录、路由和候选配置。
2. 准备本地文件服务。
3. 注册资源隧道。
4. 自动同步云端 Nginx 入口。
5. 检查实际 HTTPS 资源响应。

浏览器不需要一直等待请求。应用返回异步操作，进度可在“操作记录”查看。

## 判断是否生效

“已生效”表示指定资源版本通过了实际探针检查。文件服务或隧道进程正在运行，不足以证明项目已生效。

如果显示“等待隧道”“等待入口同步”或“外网待验证”，进入 [状态与故障排查](./troubleshooting.md) 定位阶段。密码资源需完成 [单独核验](./access.md)。

## 多个资源前缀

同一目录可以登记多个明确范围，例如：

```text
/blog/xxx/
/blog/photos/
```

不能同时登记 `/blog/xxx/` 与 `/blog/xxx/deep/`，也不能使用整个 `/blog/`。同站点的重复、包含或仅大小写不同的冲突范围会被拒绝。

已授权页面范围内的新前缀由工具自动同步。更换域名或扩大授权页面范围，需要云端管理员明确授权。

## 修改目录或配置

编辑并保存普通修改后，点击“应用”使新版本生效。仅保存不会自动把修改全部发布。

迁移根目录时保持页面基础路径与资源前缀不变，资源 URL 也不变；路由清单未变时不会重载云端 Nginx。

更换访问策略、资源用户名或密码会先阻断并停用，需要重新确认应用。站点或页面基础路径变更需要先停用、删除映射并释放旧路径，再建立新映射。

## 导出草稿配置

“导出草稿配置”导出项目结构，不包含连接材料、密码或探针。导入形成草稿，不会自动公开项目；密码项目需要重新设置资源密码。

具体命令见 [CLI 参考](../reference/cli.md)。
