# 认识檐渡

檐渡（Yandu）把本地目录中的图片、音频和视频，按明确指定的路径接入你已有的网站。

你在本机浏览器中管理项目；正式部署以 Windows 客户端为目标，当前 macOS 可通过 [开发模式](./development.md) 从源码使用。文件留在本地磁盘，云端网站继续提供页面和业务 API，只把登记的资源前缀转入文件链路。

## 一个实际例子

假设博客页面在 `https://example.com/blog`，素材存放于 `D:/oss/blog`：

| 请求 | 谁提供内容 |
| --- | --- |
| `/blog` | 原来的云端博客 |
| `/blog/posts/123` | 原来的文章页面 |
| `/blog/api/users` | 原来的业务 API |
| `/blog/xxx/photo.png` | 本地文件 `D:/oss/blog/xxx/photo.png` |
| `/blog/xxx/missing.png` | 资源 404，文件不存在时不会返回博客首页 |

你登记的资源前缀是 `/blog/xxx/`，而不是整个 `/blog/`。

## 两端分别做什么

| 位置 | 你要准备什么 | 檐渡负责什么 |
| --- | --- | --- |
| Windows 本机 | 素材目录、安装账户、目录读取权限 | 项目管理、文件检查、本地文件服务、隧道客户端 |
| 云端服务器 | 既有网站、域名、HTTPS、宿主机 Nginx | 资源路径分流、隧道服务、受限配置助手 |

SSH 用于同步资源路径配置；实际文件通过 frp 隧道读取。关闭管理页面不会关闭后台服务。

## 发布的范围

- 项目默认未发布，保存后需要明确确认应用。
- 只支持公开只读或独立密码保护，资源入口只接受 GET/HEAD。
- 默认媒体白名单；HTML、JavaScript、SVG 和目录列表不能作为业务素材发布。
- 删除映射不会删除磁盘文件。
- 博客原有的文章发布流程继续负责文章和素材发布规则。请把根目录指向允许公开的素材出口。

## 运行边界

文件没有被复制成云端备份。本机关机、休眠、断网或磁盘不可读时，资源会不可用，云端页面继续运行。
