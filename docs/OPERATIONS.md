# 运维、恢复与轮换

## 日常状态

用桌面快捷方式或 `yandu ui` 打开管理页。Agent、Caddy、frpc 进程、连接材料和各项目实际状态分开显示。“隧道客户端运行”不表示所有代理已注册；“连接材料已导入”不表示 SSH 当前在线。实际项目状态以隧道注册和随机 HTTPS 资源探针为准。

导出诊断文件只含版本、组件是否安装、路由版本和脱敏操作，不包含目录、SSH 密钥、隧道 token、明文密码。详细本机错误留在状态页与本机日志，不自动传给云端。

生成配置和子进程日志位于状态目录。运行数据以 SQLite 为准；日志和 generated 目录需要定期归档，首版不承诺无限长期保留的磁盘配额。后台子进程退出时退避重启；新的配置保留为重启参数。目录不可用时不能回退父目录，保持阻断并在恢复时重试。

## 失败与重试

- 目录/ACL 错误：检查路径、LocalService 权限、磁盘解锁和链接，修复后应用。
- 隧道未注册：检查 frps 7000、token、CA、serverName、证书有效期。管理页继续可用。
- SSH 离线：已有文件通道继续工作，新入口同步保持待处理；不要重开已经停用的资源。
- SSH 主机指纹改变：查明服务器变更并重新安全配对，不自动信任新主机。
- Nginx 无效：修复云端全局/站点冲突，再重试。旧运行配置不因校验失败被重载；停用的本地资源继续被阻断。
- 外网待验证：检查 DNS/TLS、入口配置或资源密码。通用 SPA 200 不是成功。
- CONFIG_DRIFT：root 管理员核对外部修改与 generation，不手改 generated 文件欺骗状态。

应用操作异步执行。访问权限或密码变更会先停用，需重新确认应用。普通待收敛状态每 30 秒重试；草稿和仅保存的普通修改不会自动发布。密码资源等待用户输入密码核验。重启把未完成操作标为 interrupted，校验现有目录后重建组件，再核对云端回执与资源链路。

## 停用、删除与释放

停用先在本地阻断，然后撤销代理/同步拒绝 location。删除映射复用停用流程，成功后移除项目并保留旧路径记录。均不删素材。

独立“释放给网站”会移除云端拒绝规则，使原网站重新处理该前缀；必须明确确认。若网络中断，持久化的 pending 清单保留这个意图，后续查询回执继续恢复。

云端紧急封禁：`sudo bash block-cloud.sh --site main` 将站点标记为 blocked 并停止/禁用共享资源隧道的开机启动，普通设备同步无法清除封禁。解封由 root 管理员明确修改 blocked 字段并核对配置后明确 enable --now 启动服务。必要时再撤销 `/etc/ssh/yandu_authorized_keys` 中设备公钥并禁用固定 sudo 权限；确保客户端不能同步恢复。依据受管记录生成拒绝路由并执行 `nginx -t`/reload。云端管理员的封禁不能仅改一个仍允许同一设备覆盖的 location。恢复前应重新配对、审阅目标配置，不能让旧设备凭据自动重新获权。

## 升级与卸载

Windows：完整新包运行 `upgrade-windows.ps1`。先停服务，备份 DB/WAL 和旧程序组件，更新并检查管理健康。失败恢复旧程序和对应数据库备份。当前数据库模型没有不可逆迁移；未来增加迁移必须另设回退门槛。Windows 脚本的 SCM/ACL 行为尚需真机验收。

Linux：`sudo bash upgrade-cloud.sh` 备份自己的 helper/frps，校验配置后重启 frps；组件重连会影响当前资源连接。Nginx 业务服务不重启。

卸载前先停用项目，等云端回执成功。

- Windows `uninstall-windows.ps1`：删除归属记录中的程序、服务、快捷方式；保留 ProgramData 和业务资源。
- Linux `uninstall-cloud.sh`：停隧道、生成受管拒绝规则、移除固定账号的 SSH/sudo 入口及自己的程序；保留 `/etc/yandu` 和拒绝 include，防止掉回 SPA。不会覆盖或删除原网站。

## 凭据与证书轮换

隧道叶证书由安装器生成，有效 365 天；CA 有效 10 年。证书到期前在 root 控制的 TLS 目录生成新 server key/cert，SAN 必须匹配连接包 TLSName；校验后重启 frps。如果 CA 不变，frpc 不需要导入新 CA，但会重连。更换 CA 时先生成包含新 CA 的加密连接包，分阶段导入；不要同时撤掉仍在使用的旧信任链。

共享 tunnel token 和 SSH 设备密钥轮换与普通项目热更新分开。首版配对命令拒绝直接新增第二台设备；轮换时 root 管理员备份注册表、撤销旧公钥，清除旧设备登记并通过 `yandu-cloud pair` 生成新专用设备材料，再更新固定 sudo principal 和公钥文件。Windows 导入新包会停用现有资源，重新确认应用后恢复。旧加密包备份也应作废管理。

这次发行提供原语及运维流程，不提供未经验证的“一键无感轮换”按钮。
